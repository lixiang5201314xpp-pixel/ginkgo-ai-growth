# 36.16.1 四人混合团体比赛实跑与优化

已将11月18日“银杏杯”128名真实报名人员复制到连接专属临时SQL表，使用当前正式后台处理逻辑、实际前端页面方法与本机HTTP接口，完整跑完32队、两个组、48场小组赛及16场淘汰/决赛/季军赛。所得比分是隔离测试数据，未录入正式比赛。正式比赛只读核对仍为128人、尚未分队。

## 本轮修改

- 团体管理和对阵页在前台每10秒更新；离开页面停止，排阵草稿、录分弹窗和保存期间受到保护。
- 对方交齐盲排后自动显示对阵单，已提交方明确显示等待状态。
- 进行中的团体比分直接显示，例如“1 : 0 · 进行中”，结束后显示已完成。
- 人员入口和提示更新为直接查看/更换人员；对阵页可以返回团体赛程。
- 解决后台刷新正在返回时覆盖输入，以及保存后的最新读取被旧请求挡住的问题。

仅修改6份前端文件，后台仍使用已安装且重新核对的miniapp-update1.3.0 / four-team1.2.0，无需再次安装服务器程序。

完整流程包含双方队长各自盲排、另一方未提交前不可见；普通裁判录分而不能更正已确认比分；裁判长说明原因更正；非法11:10拒绝并保留输入；双打不产生个人积分；两组小组出线、决赛与季军赛以及最终前三名。测试客户端发出1097次实际请求，使用真实处理逻辑而非预制API响应。

另在新私有副本验证逐人换人自动创建未注册账号、保留已打盘和旧积分归属，取消赛程保留32队并撤回本场积分，再生成48场；取消分队后删除1人，127人拒绝生成，按手机号重导找回两项积分，确认无身份证记录的性别生日后恢复128人，重新生成32队48场。真实微信手机号授权和支付不在此次私有测试中冒充通过。

一次隔离数据库连接在事务回滚处停滞；记录定位后关闭该测试进程，连接专属临时表随连接清理。重建连接后19项生命周期复测通过。此问题未作为线上软件缺陷归因。最终测试服务已正常关闭、事务回滚，测试工程已关闭。

正式安装回执11个更新文件和10个保留文件、线上7模块与6项匿名修改权限拒绝重新核对正常，测试后台代码hash与正式安装回执一致。无正式比赛、人员、订单、积分写入，无客服消息或AI调用。微信客服及20/30次限制未改。外部获客Agent继续暂停。
